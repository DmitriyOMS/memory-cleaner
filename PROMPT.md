# Промт для создания программы «Диспетчер выгрузки памяти» (Memory Cleaner 2.0)

Скопируйте весь текст ниже в AI-ассистента для программирования. Документ содержит полное техническое задание и не требует знания предыстории проекта.

---

Ты — опытный разработчик C#, .NET и WPF. Создай с нуля законченное desktop-приложение для Windows под названием **Memory Cleaner 2.0**, с русским названием окна **«Диспетчер выгрузки памяти»**. Не ограничивайся примером или макетом: создай все исходные файлы, подключи ресурсы, собери проект и проверь основной сценарий работы.

## 1. Назначение программы

Приложение должно:

- показывать запущенные процессы Windows, сгруппированные по имени программы;
- показывать количество процессов в каждой группе и суммарный рабочий набор памяти;
- отображать общий объём физической ОЗУ, занятый и свободный объёмы;
- позволять искать программы по имени, описанию и компании;
- позволять вручную отмечать несколько программ независимыми флажками;
- автоматически выбирать все незащищённые программы, у которых есть главное окно;
- показывать примерный суммарный объём памяти выбранных программ;
- после явного подтверждения пользователя закрывать выбранные программы;
- сначала пытаться корректно закрыть окна, затем принудительно завершать оставшиеся процессы;
- показывать отдельный результат по каждой программе: успех, частичный успех, не найдена или ошибка;
- обновлять список после операции.

Это не монитор в реальном времени и не фоновый оптимизатор. Программа ничего не выгружает автоматически, не работает службой, не использует интернет и не отправляет список процессов на внешний сервер.

## 2. Обязательные технологии и ограничения

Используй только:

- Windows 10/11;
- C#;
- .NET 10;
- WPF на `Microsoft.NET.Sdk`;
- XAML;
- стандартные библиотеки .NET;
- `System.Diagnostics.Process` для процессов;
- Win32 `GlobalMemoryStatusEx` через P/Invoke для сведений об ОЗУ.

Целевая платформа проекта: `net10.0-windows`.

Не используй:

- Electron, Node.js, Express, браузерный интерфейс или локальный веб-сервер;
- WinForms, MAUI, Avalonia или UWP;
- сторонние NuGet-пакеты;
- MVVM-фреймворки;
- PowerShell, `taskkill` или WMI для завершения процессов;
- автоматическое повышение прав администратора;
- автоматическую выгрузку по таймеру или порогу памяти;
- сохранение процессов, настроек или результатов в файлы или реестр.

Для сборки должен быть нужен только .NET 10 SDK с поддержкой Windows Desktop. Для запуска framework-dependent сборки на другом компьютере потребуется **.NET 10 Desktop Runtime**.

## 6. Базовые классы и команды

### `ObservableObject`

Реализуй `INotifyPropertyChanged` и generic-метод `SetProperty<T>`:

- сравнивай старое и новое значение через `EqualityComparer<T>.Default`;
- при изменении присваивай поле и вызывай `PropertyChanged`;
- используй `[CallerMemberName]`;
- возвращай `true`, если значение изменилось, иначе `false`.

### `RelayCommand`

Реализуй `ICommand` с делегатами `Action` и необязательным `Func<bool>`. Добавь публичный `RaiseCanExecuteChanged()`.

### `AsyncRelayCommand`

Реализуй `ICommand` с `Func<Task>` и необязательным `Func<bool>`:

- `Execute` может быть `async void` только как адаптер `ICommand`;
- предоставь `Task ExecuteAsync()`;
- добавь `RaiseCanExecuteChanged()`.

Команды должны заново проверять доступность при изменении занятости и выбора.

## 7. Модели данных

### `ProcessGroup`

Наследуй `ObservableObject` и добавь:

- `Name: string` — обязательное init-only свойство;
- `Description: string`;
- `Company: string`;
- `ProcessCount: int`;
- `MemoryBytes: long`;
- `HasWindow: bool`;
- `IsProtected: bool`;
- `IsSelected: bool` с уведомлением об изменении.

Вычисляемые свойства:

- `MemoryMB = MemoryBytes / 1024 / 1024`;
- `CanUnload = !IsProtected`;
- `DisplayDescription` — описание или `—`;
- `DisplayCompany` — компания или `—`;
- `SafetyLabel`:
  - защищённый процесс — `системный`;
  - незащищённый с окном — `можно выгрузить`;
  - остальной — `фоновый`;
- `WindowLabel`: `Есть окно приложения` или `Без главного окна`.

Сеттер `IsSelected` обязан принудительно записывать `false` для защищённой группы. Это требование действует даже при попытке установить значение из кода.

### Снимок процессов и памяти

Создай:

```csharp
public sealed record ProcessListSnapshot(
    IReadOnlyList<ProcessGroup> Applications,
    MemorySnapshot Memory);
```

`MemorySnapshot` хранит `TotalBytes` и `AvailableBytes` как `ulong` и вычисляет:

- `TotalGB`;
- `AvailableGB`;
- `UsedGB = max(0, TotalGB - AvailableGB)`.

Для ГБ делай последовательно три раза на 1024.

### Результат выгрузки

Создай enum `UnloadStatus`:

```text
Completed
Partial
Failed
NotFound
```

`UnloadResult` должен содержать `Name`, `Status`, `ClosedCount`, `TotalCount`, `FreedMB` и необязательный `Error`.

Тексты результата:

- `Completed`: `выгружена, освобождено примерно {FreedMB:N0} МБ`;
- `Partial`: `выгружена частично: {ClosedCount} из {TotalCount} процессов`;
- `NotFound`: `уже не запущена`;
- `Failed` без ошибки: `не удалось завершить процессы`;
- `Failed` с ошибкой: `не удалось завершить процессы: {Error}`.

## 8. Получение списка процессов

В `ProcessService` реализуй синхронный метод получения снимка и асинхронную обёртку через `Task.Run`, чтобы не блокировать UI.

Алгоритм:

1. Вызови `Process.GetProcesses()`.
2. Освобождай каждый объект `Process` через `using`.
3. Получай `ProcessName`; если процесс уже завершился или недоступен, пропускай его.
4. Группируй процессы по имени без учёта регистра.
5. Для каждой группы накапливай:
   - количество процессов;
   - сумму `WorkingSet64`;
   - признак наличия главного окна хотя бы у одного процесса;
   - первые доступные метаданные `FileDescription` и `CompanyName` из `process.MainModule?.FileVersionInfo`.
6. Если отдельный процесс не даёт доступ к памяти, окну или метаданным, не прерывай всё сканирование. Для памяти используй 0, для окна — `false`, для метаданных — пустые строки.
7. Обрабатывай ожидаемые ошибки процессов: `InvalidOperationException`, `NotSupportedException`, `Win32Exception`, `UnauthorizedAccessException`.
8. Создай `ProcessGroup` для каждого аккумулятора и верни массив групп вместе со снимком ОЗУ.

Главное окно определяется условием:

```csharp
!process.HasExited && process.MainWindowHandle != IntPtr.Zero
```

Название группы должно быть именем процесса без `.exe`, например `notepad`, `chrome`, `explorer`.

## 11. Получение сведений об ОЗУ

Объяви через `DllImport("kernel32.dll", SetLastError = true)`:

```csharp
private static extern bool GlobalMemoryStatusEx(ref MemoryStatusEx buffer);
```

Добавь `[return: MarshalAs(UnmanagedType.Bool)]`.

Структура `MemoryStatusEx` с `LayoutKind.Sequential` должна содержать в указанном порядке:

```text
uint Length
uint MemoryLoad
ulong TotalPhysicalMemory
ulong AvailablePhysicalMemory
ulong TotalPageFile
ulong AvailablePageFile
ulong TotalVirtual
ulong AvailableVirtual
ulong AvailableExtendedVirtual
```

Перед вызовом установи `Length = Marshal.SizeOf<MemoryStatusEx>()`. При успеху верни общую и доступную физическую память. При неудаче верни нули, а UI должен показать `Показатели ОЗУ недоступны`.

## 12. Алгоритм выгрузки

Публичный сервисный метод принимает имена групп, а не доверенные объекты из UI.

Перед началом:

- удали пустые имена;
- удали защищённые имена и имя собственного процесса;
- удали дубликаты без учёта регистра;
- обрабатывай группы последовательно.

Для каждой программы:

1. Повторно вызови `Process.GetProcessesByName(name)` в момент операции.
2. Если процессов нет, верни `NotFound`.
3. Запомни исходное количество и сумму `WorkingSet64`.
4. Для каждого процесса:
   - если он уже завершился, пропусти;
   - если есть главное окно и `CloseMainWindow()` вернул `true`, не вызывай `Kill()` на этом проходе;
   - иначе вызови `Kill()`;
   - сохрани первое сообщение ожидаемой ошибки процесса.
5. До 2 секунд жди завершения процессов, проверяя список каждые 100 мс.
6. Для всех оставшихся процессов с этим именем вызови `Kill()`; ожидаемые ошибки сохраняй, не прерывая обработку остальных.
7. Подожди ещё до 500 мс с тем же интервалом проверки 100 мс.
8. Посчитай оставшееся количество и `ClosedCount = max(0, TotalCount - RemainingCount)`.
9. Определи статус:
   - осталось 0 — `Completed`;
   - закрыто больше 0, но что-то осталось — `Partial`;
   - не закрыто ничего — `Failed`.
10. Рассчитай приблизительно освобождённую память пропорционально:

```text
FreedBytes = MemoryBefore × ClosedCount / TotalCount
FreedMB = FreedBytes / 1024 / 1024
```

Не выдавай эту оценку за точное измерение: в тексте всегда используй слово `примерно`.

## 13. Поведение `MainViewModel`

Создай коллекции:

- `Apps: ObservableCollection<ProcessGroup>`;
- `Results: ObservableCollection<UnloadResult>`;
- `AppsView: ICollectionView` через `CollectionViewSource.GetDefaultView(Apps)`.

Настрой:

- фильтр `AppsView.Filter`;
- начальную сортировку по `MemoryBytes` по убыванию.

Команды:

- `RefreshCommand`;
- `SelectSafeCommand` — несмотря на имя команды, она выбирает все **незащищённые группы с главным окном**, а не гарантирует безопасность;
- `ClearSelectionCommand`;
- `UnloadCommand`.

Начальные тексты:

```text
MemoryText = ОЗУ: загрузка…
StatusText = Подготовка списка процессов…
SelectionText = Ничего не выбрано
```

При загрузке окна один раз вызови `InitializeAsync()`, которое запускает обновление.

### Обновление

- Не запускай второе обновление во время `IsBusy`.
- Во время операции устанавливай `IsBusy = true` и `StatusText = Обновление списка процессов…`.
- После получения снимка отпишись от `PropertyChanged` старых групп, очисти коллекцию и добавь новые группы.
- Сбрасывай выбор всех новых групп и подписывайся на их `PropertyChanged`.
- Обнови текст ОЗУ:

```text
ОЗУ: {UsedGB:N1} ГБ занято из {TotalGB:N1} ГБ · свободно {AvailableGB:N1} ГБ
```

- После успеха:

```text
Приложений: {Apps.Count} · обновлено {DateTime.Now:HH:mm:ss}
```

- При ошибке покажи сообщение и установи `Не удалось обновить список процессов`.
- В `finally` всегда снимай `IsBusy`.

### Поиск

Поиск срабатывает на каждое изменение текста и обновляет `AppsView`. Пустой поиск показывает всё. Сравнение без учёта регистра — `OrdinalIgnoreCase` по:

- `Name`;
- `Description`;
- `Company`.

Поиск только фильтрует представление и не должен сам снимать отметки с других групп.

### Выбор

- Кнопка `Выбрать оконные` устанавливает `IsSelected = true` всем группам, где `CanUnload && HasWindow`.
- `Снять выбор` очищает выбор во всей коллекции.
- При изменении любого флажка обновляй нижний текст и доступность команд.
- Если выбранных нет: `Ничего не выбрано`.
- Иначе:

```text
Выбрано: {количество} · примерно {сумма MemoryMB:N0} МБ
```

Доступность:

- обновление и автоматический выбор — только когда не `IsBusy`;
- снятие выбора — когда не `IsBusy` и есть хотя бы один выбранный элемент;
- выгрузка — когда не `IsBusy` и есть выбранный элемент с `CanUnload`.

### Подтверждение выгрузки

Перед операцией сформируй `MessageBox` с `YesNo`, иконкой `Warning` и результатом по умолчанию `No`.

Текст:

```text
Будут закрыты приложения ({количество}):
• {имя 1}
• {имя 2}

Ожидаемое освобождение: примерно {сумма:N0} МБ.
Несохранённые данные могут быть потеряны. Продолжить?
```

Показывай не более 12 имён. Если программ больше, добавь строку `• и ещё {N}`. Заголовок: `Подтверждение выгрузки`.

Если ответ не `Yes`, ничего не делай. Кнопка «Нет» и Escape должны быть безопасным вариантом.

### Выполнение выгрузки

- Установи занятость и текст `Выгрузка выбранных приложений…`.
- Вызови сервис с именами выбранных незащищённых групп.
- Замени содержимое `Results` полученными результатами.
- Показывай панель результатов, только если коллекция не пуста.
- Обнови снимок процессов, не выполняя вторую повторную проверку занятости внутри общего метода снимка.
- В конце:

```text
Операция завершена: успешно {количество Completed} из {всего результатов}
```

- При исключении: `Не удалось завершить операцию` и MessageBox с текстом ошибки.
- Всегда снимай занятость в `finally`.

## 14. Главное окно и стиль

## 15. Жизненный цикл и ошибки

В `App.OnStartup`:

- установи культуру `ru-RU` для текущего потока и как `DefaultThreadCurrentCulture` / `DefaultThreadCurrentUICulture`;
- зарегистрируй `DispatcherUnhandledException`.

Глобальная ошибка должна показывать:

```text
Не удалось выполнить операцию.

{Exception.Message}
```

Заголовок `Ошибка`, иконка Error. После показа установи `e.Handled = true`.

При закрытии главного окна во время `IsBusy` отменяй закрытие и показывай:

```text
Дождитесь завершения текущей операции.
```

Заголовок: `Операция выполняется`.

Не оставляй после закрытия фоновый сервер, поток с бесконечным циклом или процесс-помощник.

## 16. Сборка и запуск

Из корня созданного проекта выполни:

```bash
dotnet restore native/MemoryCleaner.csproj
dotnet build native/MemoryCleaner.csproj --configuration Debug --no-restore
dotnet run --project native/MemoryCleaner.csproj
```

Основной EXE после Debug-сборки:

```text
native/bin/Debug/net10.0-windows/MemoryCleaner.exe
```

Для Release-сборки без включения рантайма:

```bash
dotnet publish native/MemoryCleaner.csproj --configuration Release --runtime win-x64 --self-contained false
```

Не заявляй, что такая сборка полностью автономна: на компьютере пользователя нужен .NET 10 Desktop Runtime.

## 17. Обязательная проверка

После написания кода самостоятельно выполни сборку. Она должна завершиться с **0 ошибок и 0 предупреждений**. Затем проверь приложение в реальном запуске, а не только чтением кода.

Проверочный список:

1. Окно открывается по центру с правильным названием, значком и русскими текстами.
2. Список процессов загружается без ручного обновления.
3. Одинаковые имена процессов объединены; количество и память суммируются.
4. По умолчанию самые памятьёмкие группы находятся выше.
5. Показатели ОЗУ заполнены; значения имеют один знак после запятой в русской культуре.
6. Поиск работает без учёта регистра по имени, описанию и компании.
7. F5 повторно обновляет данные и сбрасывает прежний выбор.
8. У `explorer`, `svchost`, `dwm`, `powershell`, `cmd` и собственного `MemoryCleaner` флажки недоступны.
9. Даже программная установка `IsSelected = true` защищённой группе невозможна.
10. `Выбрать оконные` выбирает только незащищённые группы с окнами.
11. `Снять выбор` очищает все отметки.
12. Нижняя строка правильно показывает число выбранных групп и оценку памяти.
13. Пока нет выбора, кнопка выгрузки недоступна.
14. При подтверждении вариант по умолчанию — «Нет»; отмена не завершает процессы.
15. При выборе более 12 программ список в диалоге сокращается строкой `и ещё N`.
16. Запусти новый безопасный тестовый экземпляр «Блокнота» без важных несохранённых документов. Выбери только его, подтверди выгрузку и убедись, что процесс закрылся, появился результат и список обновился.
17. Панель результатов появляется после операции. При обычном обновлении списка последний результат сохраняется; перед новой выгрузкой старые результаты заменяются новыми.
18. Во время длительной операции таблица отключена, виден индикатор, повторные команды недоступны, закрытие окна блокируется с предупреждением.
19. Недоступные или уже завершённые процессы не приводят к падению всего сканирования.
20. Приложение не обращается к сети и не выполняет выгрузку без явного подтверждения.

Не проводи разрушающие проверки на системных процессах, браузере пользователя, терминале, IDE или программах с несохранёнными данными. Для практической проверки используй только специально запущенное безопасное приложение.
